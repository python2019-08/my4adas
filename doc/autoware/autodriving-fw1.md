# 1.自动驾驶软件架构：模块划分 + 完整数据流向
> 以Autoware（ROS2）这种**模块化自动驾驶栈**为参考，和你当前做巡逻机器人（定位/规划/控制，暂不用深度学习感知）场景对齐。
> 整体链路：**感知 → 定位 → 预测 → 规划 → 控制 → 车辆执行**，同时所有模块依赖**地图**，并输出监控日志。

## 一、模块清单（区分【必须】和【可选深度学习感知】）
✅ 你当前最小环境（巡逻机器人，只编译核心）：**定位、规划、控制、地图**
❌ 可跳过：深度学习感知、目标预测（简单巡逻可不用）

| 模块 | 作用 | 输入数据 | 输出数据 |
|---|---|---|---|
| 地图模块 Map | 静态地图：车道、禁行区、道路边界、参考路线 | 预先制作的点云地图/矢量地图 | HD Map矢量信息、道路拓扑、参考路径 |
| 定位 Localization | 输出机器人/车辆在地图坐标系下的实时位姿(x,y,yaw,速度) | 激光雷达点云 + IMU + 轮速里程计 + HD地图 | 自车实时位姿 `Odometry/Pose` |
| 感知 Perception | 识别障碍物、行人、车辆（深度学习/传统点云） | 激光点云、相机图像 | 障碍物列表：位置、尺寸、速度、类别 |
| 预测 Prediction | 预测周围障碍物未来运动轨迹 | 感知障碍物结果 + 地图 | 障碍物未来轨迹序列 |
| 规划 Planning | 全局路径 + 局部轨迹 | 自车位姿、地图、障碍物、目标点 | 平滑行驶轨迹（带时间戳的一系列参考点） |
| 控制 Control | 跟踪规划输出轨迹，计算控制指令 | 参考轨迹 + 自车当前状态 | 油门/刹车/转向指令（机器人：速度+角速度） |
| 车辆接口 Vehicle Interface | 下发指令给底盘，读取底盘反馈 | 控制指令 | 底盘状态（实际速度、转向角） |

## 二、完整正向数据流向（标准自动驾驶）
```
[传感器硬件]
    ↓
感知模块 → 障碍物信息
定位模块 → 自车在地图中的位姿
    ↓
预测模块（感知输出作为输入）
    ↓
规划模块（输入：地图 + 自车位姿 + 障碍物+预测轨迹 + 目标点）
    ↓
控制模块（输入：规划轨迹 + 当前自车状态）
    ↓
车辆底盘接口
    ↓
底盘执行电机/转向，同时回传底盘状态，闭环
```

### 简化版（你的巡逻机器人，Autoware最小化版本，跳过深度学习感知+预测）
> 巡逻场景：环境静态为主，障碍物可以只用激光传统检测，甚至简单避障。
```
传感器（LiDAR + IMU + 轮速里程计）
    ├─→ 定位模块 → 自车位姿
    └─→ 简易感知（传统点云障碍物检测，无深度学习）→ 障碍物
地图模块（预加载地图+巡逻参考路线）
    ↓
规划模块：全局巡逻路线 + 局部避障轨迹
    ↓
控制模块（MPC / Pure Pursuit）输出目标速度、角速度
    ↓
底盘驱动 → 机器人运动
```

## 三、关键数据流细节（ROS2话题视角，Autoware）
1. **定位输出话题** `pose` / `odom`
    整个系统的**时间与坐标基准**，规划、控制都依赖它。**定位是核心底座**，定位不准后面全部失效。
2. **地图**：静态数据，启动加载，一般不高频发布。
3. **感知障碍物**：`/perception/object_recognition/objects`
4. **规划输出轨迹**：`/planning/scenario_planning/trajectory`
    一串带时间戳的参考点：每个点包含 x,y,yaw,目标速度。**这是规划和控制之间最重要的接口**。
5. **控制输入**：上面的轨迹 + 自车odom；输出控制指令 `/control/command/control_cmd`
6. **底盘反馈**：`/vehicle/status`，回传给控制模块做闭环。

## 四、反馈回流（闭环，非常重要）
不是单向流水线：
- 底盘**实际速度、转向**会回传给控制模块做闭环修正；
- 自车实时位姿持续喂给规划模块，规划不断重新生成局部轨迹；
- 感知持续扫描环境，一旦发现新障碍物，立刻送入规划，重新规划避障路径。

## 五、模块之间的依赖关系总结
1. **地图是基础静态数据**
2. **定位是动态基准，所有模块都需要知道“我在哪”**
3. **感知负责“环境里有什么”**
4. **预测推测障碍物接下来会怎么走**
5. **规划决定“我们应该走哪条路”**
6. **控制负责“精准沿着这条路跑”**
7. **底盘执行并反馈真实状态，形成闭环**

## 六、针对你Autoware最小化编译方案的精简要点
> 你选择：不编译acados、spconv、深度学习感知
1. 砍掉深度学习感知模块 → 不用相机神经网络识别；可以保留传统激光障碍物检测。
2. 可以**不启用预测模块**，规划只做静态障碍物碰撞检查。
3. 核心链路只剩下：`定位 → 规划 → 控制`，这三块就是你要编译的主体。
4. 推荐先用纯预定义巡逻路线跑通定位+规划+控制，再加入障碍物。
