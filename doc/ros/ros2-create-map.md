# ch1.slam_toolbox 三大核心建图/运行模式（ROS2官方定义）
> 注意：**纯定位模式不算建图**，3种建图模式：**同步建图、异步建图、终身建图(Lifelong Mapping)**

## 1. 同步建图 Synchronous（online_sync）
- 逻辑：**每帧激光扫描必须完整处理完，才接收下一帧**，严格按传感器时序执行图优化。
- 优点：地图质量最高，回环优化最完整；适合小场景、算力充足、追求高精度地图。
- 缺点：大场景/高算力压力下容易**延迟、卡顿**，扫描堆积，实时性差。
- 启动文件：`online_sync_launch.py`

## 2. 异步建图 Asynchronous（online_async，**最常用**）
- 逻辑：激光扫描进来先缓存，后台线程**尽力处理**，不阻塞传感器接收；丢帧优先保证实时性。
- 优点：实时性强，大场景、嵌入式/算力一般机器人首选；工业、室外巡逻大多用这个。
- 缺点：极端高速运动下，少量扫描帧会被跳过，地图精度略低于同步。
- 启动文件：`online_async_launch.py`（你城市巡逻机器人推荐这个）

## 3. 终身建图 Lifelong Mapping（lifelong）
- 逻辑：持续长期建图，自动**裁剪冗余图节点**，限制图规模不会无限膨胀；支持加载旧地图继续探索新区域，同时自动移除过时/动态物体留下的地图痕迹。
- 优点：适合**长期巡检、城市道路、环境会缓慢变化**场景（你的巡逻机器人非常适合），可以多次开机不断迭代地图，不会越跑越卡。
- 缺点：计算开销更大，参数调优更复杂；需要保存 `.posegraph` 序列化文件（不是普通pgm地图）。
- 启动文件：`lifelong_launch.py`

---

# 补充：纯定位模式 Localization（单独模式，不是建图）
加载已经建好的posegraph地图，**不再新增地图节点**，只做定位。相当于AMCL替代品，适合正式巡逻导航阶段。

## 对比简表
|模式|适用场景|特点|推荐度（你的城市巡逻机器人）|
| ---- | ---- | ---- | ---- |
|同步建图|小场景，一次性高精度建图|质量最高，容易卡顿|⭐⭐|
|异步建图|一次性大范围建图，实时性优先|均衡，工业最通用|⭐⭐⭐⭐⭐（建图阶段首选）|
|终身建图|长期多次巡逻、地图持续更新|自动剪枝，长期运行不膨胀|⭐⭐⭐⭐（上线长期巡检用）|

> 结合你的机器人（RTK+IMU+轮速+100m激光）：
> 1. 初次采集地图：**异步建图模式**跑一遍，保存posegraph
> 2. 日常巡逻：可以直接切**纯定位模式**；如果需要地图随环境变化更新，使用**lifelong终身模式**

# ch2. Gmapping（slam_gmapping）
> **核心：经典RBPF（Rao-Blackwellized粒子滤波）2D激光SLAM，只做2D栅格地图，ROS1原生，ROS2有移植包`slam_gmapping`**


## 原理
- 输入：**激光雷达scan + 里程计odom（tf）**
- 每个粒子代表机器人一条可能的运动轨迹，**每个粒子自带一张子地图**；
- 激光扫描匹配更新粒子权重，权重低的粒子被淘汰、高权重粒子复制（重采样）；
- 没有**独立显式回环检测+全局图优化**，回环靠粒子滤波概率性修正，大场景回环容易错位。

## ✅ 优点
1. 小场景CPU开销很低，室内小房间/小仓库建图速度快；
2. 长走廊低特征环境，里程计正常时表现稳定；
3. 参数少，上手简单，调试门槛低。

## ❌ 致命短板（对你城市巡逻机器人重点看）
1. **极度依赖里程计**，里程计打滑、漂移大，地图直接错位；
2. **场景越大，内存爆炸**：粒子越多，内存占用线性暴涨，**不适合大范围城市道路**；
3. **没有全局图优化**，长距离跑一圈闭合回环极易地图撕裂；
4. ROS2社区维护弱，不是官方主推方案；
5. 只能一次性建图，**不支持保存posegraph、不能增量更新地图**，建完只能导出pgm+yaml静态地图，不能继续迭代。

## 话题与TF
- 订阅：`/scan`激光、`tf`（odom → base_link，base_link→laser）
- 发布：`/map`栅格地图、`tf(map→odom)`
- 保存地图：`ros2 run map_server map_saver -f xxx`

## 你的项目选型结论
> 你的场景：**城市道路大范围巡逻、RTK+IMU+轮速融合**
❌ **不推荐Gmapping**
- 城市道路属于大尺度室外场景，Gmapping天生不适合；
- 室外地面不平、打滑，里程计漂移大，gmapping没有全局优化，地图会越跑越歪；
- 不能长期增量更新地图，没法做长期巡检迭代。

✅ 对比回顾（你前面看的3个）
- **slam_toolbox**：图优化Karto，支持异步/同步/终身建图，支持posegraph保存，室外大范围首选
- **cartographer**：图优化，回环强，参数多，适合室外大场景
- **rtabmap_slam**：支持激光+视觉，适合大规模，算力消耗更高

> Gmapping适合：**室内小房间、小仓库、扫地机器人**这种小尺度静态环境。

## 简单对比简表
|项目|Gmapping|slam_toolbox|
| ---- | ---- | ---- |
|底层算法|RBPF粒子滤波|Karto图优化|
|回环检测|无显式回环|内置回环+全局优化|
|大场景支持|差，内存爆炸|优秀，支持几万平米|
|地图增量更新|❌不支持|✅支持终身建图|
|里程计依赖|极高|中等，可融合外部位姿（RTK）|
|ROS2维护|移植包，冷门|官方主推、活跃维护|
